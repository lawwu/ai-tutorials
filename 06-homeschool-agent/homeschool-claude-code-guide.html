Workshop handout · for homeschooling parents

Run your homeschool out of a repo

Your plans, reading logs, curriculum notes, and to‑dos live in plain files. Claude reads and writes them for you — from your laptop at the kitchen table, or from your phone in the pickup line.

Setup time about 90 minutes, once Prior experience none assumed Cost a Claude subscription; GitHub is free

What you're building

Most homeschool records live in a dozen places at once: a paper planner, a shared note, three browser tabs, and your memory. This setup puts all of it in one folder of plain files — and gives you an assistant who can read every one of them before it answers you.

There are only three pieces, and you already understand two of them.

The three pieces

The folder is your binder. Files ending in .md are just typed notes; files ending in .yaml are simple lists. You can open either one in any text editor. Nothing is locked inside an app.

Claude Code is the assistant with a key to that binder. Unlike a chat window, it can open your actual files, change them, and file new ones where they belong.

GitHub is the shared filing cabinet. It holds one copy both parents can reach, keeps a dated history of every change, and is what makes the phone work at all.

Setup — six steps, in order

1

Get the two accounts

10 minutes · do this before the workshop if you can

A paid Claude plan. Go to claude.com/pricing and subscribe to Pro or Max. This is the one part that costs money, and it is required — the free Claude plan does not include Claude Code, which is the piece that can touch your files.

A GitHub account. Go to github.com/signup. Free. Pick a username you don't mind other people seeing, use an email you actually check, and turn on two‑factor authentication when it offers. Write the password down somewhere real.

GitHub is a website programmers use to store folders of files. Nothing about it assumes you write code — you're using it as a filing cabinet that never forgets. Your repository will be private, visible only to you and anyone you invite.

2

Install Claude on your computer

10 minutes · no terminal, no command line

Download the desktop app from claude.ai/download — there's a Mac version and a Windows version. Install it the way you'd install anything else, open it, and sign in with the Claude account from step 1.

At the top of the window you'll see three tabs: Chat, Cowork, and Code. You want Code. That's Claude Code with buttons instead of typing commands.

On Windows, also install Git for Windows first — local sessions need it. Macs already have what they need.

Why the app and not the website? The desktop app can open the folder on your own computer. The website version (step 5) works on the GitHub copy instead. You'll use both, for different moments.

3

Make the folder, and put it on GitHub

15 minutes · Claude does the technical part

Create an empty folder on your computer called homeschool. Documents is a fine home for it. If you already have homeschool files scattered around, don't move them yet — start empty, and add them once the shape is clear.

In the Claude app, on the Code tab, choose Local, click Select folder, and pick the folder you just made. Then paste this in and press enter:

Set this folder up as a git repository, create a new PRIVATE repository on my GitHub account called "homeschool", and push this folder to it. I've never used git or GitHub before — walk me through anything you need me to click, one step at a time.

Claude will ask permission before it runs commands — that's normal, and you should say yes to these. Partway through it will send you to a browser window to sign in to GitHub and enter a short code. That's GitHub confirming it's really you.

If it gets stuck: go to github.com/new yourself, name the repository homeschool, select Private, click Create, then come back and tell Claude “I made the empty repo at github.com/<your‑username>/homeschool — connect this folder to it and push.”

Private, not public — check this twice

This folder will hold your children's names, ages, and daily schedules. Open your repository page on github.com and confirm the word Private appears next to its name. If it says Public, tell Claude to make it private, or change it under Settings → General → Change visibility.

4

Write the instructions file

30 minutes · the step that decides whether this works

A file named CLAUDE.md at the top of your folder is read at the start of every single conversation, on every device. It's where you write down the things you'd otherwise re-explain every time: who your children are, what you believe about education, where new information goes, and what must never be written down.

This is the difference between a clever chatbot and an assistant that knows your family. Don't skip it, and don't write it alone — talk it out with Claude:

I want to write a CLAUDE.md for this folder so you know how to help with our homeschool. Interview me — ask me one question at a time, and write the file as we go. Cover: my kids and their grades, our educational philosophy, the curricula we use, our weekly rhythm, where different kinds of information should get filed, and what should never be written into these files.

Expect twenty minutes of back and forth. It's worth it. You can revise it forever — it's just a text file.

Six things every homeschool CLAUDE.md should end up containing:

SectionWhat goes in it
Who you're talking to“Optimize for a busy homeschooling mom, not a programmer. Be warm, concise, concrete.”
The familyEach child's name, birthdate, grade level. Your charter or umbrella school, if you use one.
Your philosophyWritten as rules Claude must honor. “Mastery over speed — never recommend acceleration at the cost of understanding.”
Where things get filedA short routing list. Progress in a curriculum → the child's curriculum file. Something that happened today → the journal. A decision or deadline → TODO.
Never invent factsEvery item in a plan must trace back to something you actually said or a real file. When something's missing, Claude asks — it does not fill the gap with a plausible guess.
Never write downThe list in step 6. Copy it as‑is.

Keep the routing list high‑level. Give the shape and the rules; let Claude search the folder to find specific files. A CLAUDE.md that catalogs every file in detail goes stale within a month and starts giving wrong directions.

5

Connect the phone and the browser

10 minutes · this is the part that changes your week

Go to claude.ai/code and sign in. It'll prompt you to connect GitHub — follow it, and authorize the Claude GitHub App for your account. When it offers to create a Default environment, accept the defaults.

Then install the Claude app on your phone (iOS / Android) and open its Code tab. Same account, same repositories.

Now, from a browser or a phone: pick homeschool in the repository selector, type what you want, and send. Claude spins up a machine in the cloud, works on a copy of your folder, and writes the results back. Your laptop can be shut in a bag.

Try it now, from your phone, so you've done it once before you need it:

Add a line to TODO.md: order the science supplies for next week.

Then open the diff, create the PR, and merge it. Thirty seconds. That's the loop for everything.

6

Learn the two habits

Five minutes — then it's muscle memory

Two parents and three devices all editing the same folder works fine, as long as everyone starts and ends the same way. Put these two lines in your CLAUDE.md and Claude will do them for you:

Start of every session: “Start every session with git pull.” This brings down whatever your spouse changed from their phone last night. Skipping it is the single most common source of confusion.

End of every session: “End every session by committing and pushing with a short summary of what changed.” Anything not pushed exists only on that one device.

If a push is ever rejected, it means someone else pushed first. Tell Claude “pull with rebase and push again” — it knows what to do, and this is exactly the situation version control was built for.

Nothing you do here can lose data. Every version of every file is kept. If a plan gets mangled, ask Claude to show you what it looked like last Tuesday and put it back.

What to actually ask it

Setup is the easy part; knowing what to ask is the real skill. The prompts below come from a year of real use, rewritten so you can paste them as they are. Anything in [brackets] is yours to fill in. Notice the pattern more than the wording — you're talking to it the way you'd talk to a capable assistant who has read all your files.

Capture — get things out of your head

The highest‑value habit. Talk or paste; never re‑type anything into a form. Use your phone's dictation button and don't organize as you go — that's the assistant's job.

log: read aloud this morning, [child] asked a question I couldn't answer and I still owe her one. [Older child] finished chapter 2 lesson 3 in math and it was a fight. [Younger child] did four pages and lost interest.

One messy dump, three destinations: the journal entry, the math position in the curriculum file, and the unanswered question on your to‑do list. You never open those files yourself.

These are the books [child] finished this month, plus her own summaries. Record them in her reading log and keep her wording exactly as written — don't clean it up.
Capture this feedback from [child]'s [writing teacher / evaluator / tutor]: [paste the whole email]

Plan — the weekly work

Once your curriculum files and weekly rhythm are written down, these get shorter every week. Eventually they're two words.

plan this week
pacing report — are we on track to finish [subject] by [month]?

Ask it to write a small script for the arithmetic and run it, rather than doing the math in its head. Then it's the same answer every time, and you can check the script.

What do I need to do before school starts on [date]?
Break the [state] [grade] [science / social studies] standards into a weekly quota across our remaining weeks, so nothing piles up before [the deadline].

Decide — curriculum and resources

Claude can read a publisher's page and weigh it against what your children have already done and what's already on your shelves.

I'm choosing [4-6] books from this [subject] package for my [age]-year-old: [link]. Help me decide, given what she's already read and what we own.
How does [program] actually work? I signed up for an account and that's all I know. Schedule the lessons for each of my kids by grade level, and tell me what supplies I need a week ahead of each one.
I want a daily [reading / memory work / practice] plan for each child at their own level. Keep them on the same passage on the same day so I'm teaching one thing, not three — and sync it with the plan my spouse and I are already on. We're on day [N].
What would [that paid program] give me on top of what we already have?

That last one is the most underrated prompt here. It has your actual curriculum files, so it can tell you when something is a genuine gap and when you'd be paying for what you already own.

Make — things you can hold

Claude writes files, and a printable page is just a file. This is where families get the biggest surprise — so it's worth walking one all the way through. Here's how a single state standard became a deck of cards on the kitchen table.

Start with the requirement, not the craft.

One of my [grade]'s social studies standards asks her to learn how people from history made a difference in others' lives. Design a "hero of the week" habit for the whole year — one short biography a week, about ten minutes. Use the biographies we already own where you can, and fix the rotation week by week so there's no ambiguity. I'm teaching more than one child at once and I can't be deciding this on a Friday morning.

Because your bookshelves are already in the folder, it builds the rotation out of what you own and names the few you'd need to find. That last sentence is doing real work — it's the difference between a fixed table and a flexible framework you'll have to think about every week.

Then ask for the physical thing.

Now build the actual cards. One per person: their name, their portrait, and four prompts — who they were, what was hard, what they did, and what character it took. Two per landscape page with ruled lines, printed single-sided so I can cut down the middle. Write it as a script that generates the PDF, not a one-off file, so I can re-run it when the list changes.

Asking for a script instead of a document is the move worth stealing. Six weeks later you swap two names, re-run it, and get a new deck — instead of redoing the layout by hand. Same trick works for copywork pages, flashcards, and weekly checklists.

Then close the loop on the paperwork.

Which of this year's cards should go in her portfolio as work samples, and which reporting period does each one cover?

A standard, a weekly habit, a thing she can hold, and the records requirement discharged — one thread, and the child experiences it as her favorite ten minutes of the week.

Two more in the same vein:

Turn these plans into a printout I can hand to each child.
Give me 3 things each child will learn this year, grouped by subject, and why each one matters in the real world — I'm giving them a short talk to kick off the school year.

The physical world

Point your phone camera at your actual house. This one is worth demonstrating live — it's the moment the whole idea lands.

I photographed every bookshelf in the house — the photos are in this folder. List every title, then group them by which school year they'd be useful for, which to pull for this year's bins, and which to give away. Include where each one physically is, so I know which shelf to pull from.

Six months later you can ask “which shelf is [that title] on?” — and get an answer, because the location went into the file alongside the title.

Keeping the folder honest

Run these every month or two. They catch the drift that builds up when two people file things from two phones.

Review this whole folder and tell me if there are any contradictions. Then tell me how you'd improve the structure.
How do you know [that thing] is due on the 15th?

Ask this whenever something looks off. It should cite the file the fact came from. If it can't, the item was invented and should be deleted — which is exactly why the “never invent facts” rule belongs in your CLAUDE.md.

Guardrails

Your repository is private, but it does sync through GitHub and through an AI service. Names, birthdates, grades, and schedules are reasonable to keep there. Some things are not, and the list belongs in your CLAUDE.md so Claude enforces it even when you forget.

Never write these into your files

  • Your home address, or any government or school identity document
  • Social Security numbers, or your state's student ID numbers
  • Medical or health information about anyone in the family
  • Photos with a child's face in frame — photos of schoolwork are fine
  • Passwords, keys, or login tokens of any kind
  • Financial account numbers

If one of these gets committed by mistake, deleting it in a new version isn't enough — the old version is still in the history. Tell Claude right away and ask it to rewrite the history.

Keep names off the open web. Add this line too: “Never put the children's names into web searches or any external service. Research in generic terms — ‘grade 4 narration prompts,’ not a child's name.” Names inside your private folder are fine; names leaving it are not.

Journals are append‑only. “Never overwrite journal history; append only.” What happened on a Tuesday in October shouldn't be quietly rewritten in March.

Optional, later: have GitHub check your files once a week

Once you're comfortable, GitHub can run Claude on a schedule against your folder — scanning the week's changes for anything on the list above, checking that your files still parse, and opening an issue only if something's wrong. It's about thirty lines of configuration, and Claude will write it for you:

Set up a GitHub Actions workflow that runs every Monday afternoon, reviews the last week of changes against the "never write these" list in CLAUDE.md, and opens a GitHub issue only if it finds something. Read-only — it must never change or commit anything. Walk me through adding the secret it needs.

One detail worth insisting on: tell it to report findings by file and line number only, never quoting the sensitive value — otherwise the secret ends up in the log.

When something goes wrong

Claude keeps asking permission for everything

That's the default, and it's the right setting while you're learning. In the desktop app you can switch the permission mode to Accept edits once you trust it with your own folder. Read the first several changes closely either way.

My spouse's changes aren't showing up on my laptop

Say “pull the latest.” Their work is on GitHub; your laptop hasn't fetched it yet. This is why the start‑of‑session habit matters.

It says my push was rejected

Someone pushed before you. Say “pull with rebase, then push.” Nothing is lost — this is version control doing its job.

The plan it made includes something we never do

Ask “where did that come from?” It should cite a file or a conversation. If it can't, tell it to delete the item and add a line to your CLAUDE.md forbidding invented details. This happens most often when a folder is young and Claude fills gaps with generic homeschool patterns.

No repositories appear on claude.ai/code

The connected GitHub account can't see the repository. Sign in to github.com as the same account you connected, and confirm the repository is there. Private repositories work fine; they just need the same authorization.

I'm afraid I'll break something

You can't, permanently. Every version of every file is stored. The worst realistic outcome is a messy afternoon that Claude can undo by restoring an earlier version. Ask it to.

Plain English

Repository (repo)
Your folder, plus its complete history. “The homeschool repo” just means “that folder.”
Git
The system underneath that records every version. You will never need to use it directly.
Commit
A saved snapshot with a note attached: “added week 3 plans.”
Push / pull
Send your changes up to GitHub / bring the latest down to your device.
Branch
A draft copy you can change without touching the real thing. Cloud sessions always work on one.
main
The official version — what you'd print from.
Diff
A side‑by‑side of exactly what changed. Green is added, red is removed.
Pull request (PR)
“Please fold this draft into the real thing.” You review the diff, then click Merge.
Merge
Approving that fold. Now it's part of main.
Markdown (.md)
A plain text file where # makes a heading and - makes a bullet. That's most of it.
YAML (.yaml)
A plain text file for lists and settings, written as name: value. Indentation matters.
CLAUDE.md
The standing instructions Claude reads before every conversation, on every device.

Your first week

Don't try to move everything in at once. The folder should grow out of use, not out of a plan.

Day 1. Finish steps 1–6. Add one real file — a TODO.md with the three things actually nagging you.

Days 2–5. Log each day from your phone, in whatever words come out. Nothing else. Let the journal accumulate.

Day 6. Ask “what did you notice this week?” This is the moment it stops feeling like filing and starts feeling like help.

Day 7. Ask it to plan next week. Then fix what it got wrong — by adding a rule to your CLAUDE.md, so it never gets that wrong again.

That last habit is the whole thing, really. Every correction you write down once is a correction you don't repeat. The folder gets smarter because you keep teaching it, which is a job you already know how to do.
